# ذهبي · ديمو شغال (v2.0)

ديمو بكود حقيقي لنظام ذهبي بالمعمارية اللي اتعتمدت في المخطط الهندسي:
قاعدة بيانات PostgreSQL لكل محل، وقاعدة تحكم مركزية، ونظام إضافات بمتجر.

## تشغيله على جهازك

محتاج [Docker Desktop](https://www.docker.com/products/docker-desktop/) بس.

```bash
docker compose up --build
```

وبعدين افتح http://localhost:3000

- **محل جديد:** من «اشتراك محل جديد». كل محل بيتعمل له قاعدة بيانات لوحده (`tenant_<الرابط>`).
- **فريق المنصة:** `admin` / `admin123`.

## تجرب إيه

1. اشترك بمحلين مختلفين. كل واحد هيتعمل له قاعدة في أقل من ثانية، ومحدش فيهم يشوف بيانات التاني.
2. ضيف قطع في المخزون، وبيع فاتورة من نقطة البيع بسعر الذهب بتاع النهارده.
3. من متجر الإضافات ثبّت «نقاط الولاء». هتظهرلك الصلاحيات ولازم توافق عليها. بيع تاني، والنقط هتظهر في الرئيسية.
4. ثبّت «حد الفاتورة الكبيرة» وخلّي الحد 30,000. أي فاتورة أكبر هتتوقف.
5. ثبّت «الإضافة البطيئة». بتاخد ثانيتين، وذهبي بيوقفها بعد نص ثانية والفاتورة بتكمل عادي.
6. افتح «سجل الإضافات» وشوف كل إضافة اشتغلت إمتى وبنتيجة إيه ومدتها.
7. ادخل كفريق المنصة: هتشوف كل قاعدة ومكانها وحجمها وإصدارها، ومن غير ما تقدر تفتح بيانات أي محل.

## الفرق بين الديمو والإنتاج

الديمو بيوضح الفكرة كاملة، بس فيه حاجات متبسّطة عن المخطط:

- الإضافات بتشتغل بـ `node:vm`. ده **مش** عزل أمني. الإنتاج بيستخدم `isolated-vm` في خدمة لوحدها بحدود ذاكرة.
- الأحداث بتتقري من الـ outbox مباشرة كل ثانية. الإنتاج بيبعتها على NATS JetStream.
- سجل المحلات متخزن في الذاكرة. الإنتاج بيستخدم Redis.
- مفيش OTP على واتساب، ولا نقطة بيع Flutter من غير نت، ولا موجات الـ migrations، ولا النسخ الاحتياطي.
- الأسعار والبيانات للتجربة بس.

## للمطورين

```bash
# من غير Docker: محتاج PostgreSQL 16 شغال على localhost:5432
cd api && npm install && npm run dev        # الـ API على :3000
cd web && npm install && npm run dev        # الواجهة على :5173
API_URL=http://localhost:3000 npm test      # اختبار العزل (من فولدر api والسيرفر شغال)
```
